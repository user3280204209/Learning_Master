## 三、分块二：数据库（MySQL）

### 1. 查询 MySQL 执行计划 —— ✅

| 项目 | 内容 |
|---|---|
| 执行了什么 | 用 1002 行数据对比加索引前后的 `EXPLAIN`：`type` 从 `ALL` 变为 `ref`，`rows` 明显下降，`Extra` 从 `Using where` 变为 `Using index` |
| 重要知识点 | `type` 优先级 ALL < index < range < ref < eq_ref < const；`key` 看实际用了哪个索引；`rows` 是估算扫描行数；`Extra` 里的 `Using index` 表示覆盖索引 |

### 2. MySQL 存储结构 —— ✅

| 项目 | 内容 |
|---|---|
| 执行了什么 | 查看真实数据目录：每表一个 `.ibd` 文件，确认 InnoDB 页大小 16K；梳理「表空间 → 段 → 区 → 页 → 行」层次 |
| 重要知识点 | InnoDB 以页（16K）为最小 IO 单位；区（extent）默认 1MB = 64 页；聚簇索引的叶子节点直接存整行数据，所以主键查询最快；二级索引叶子存主键值，需要回表 |
| 对应文件 | `docs/lessons/11-MySQL存储引擎与执行计划.md` |

### 3. 两类重要存储引擎及配置 —— ✅

| 项目 | 内容 |
|---|---|
| 执行了什么 | 用真实实验对比 **InnoDB vs MyISAM**：事务回滚（InnoDB 回滚后 0 行，MyISAM 1 行仍在）、外键（MyISAM 静默忽略，不报错也不生效） |
| 重要知识点 | InnoDB：支持事务 / 外键 / 行锁 / 崩溃恢复（redo log）；MyISAM：不支持事务、表锁、外键只是"写着好看"。配置方式：建表 `ENGINE=InnoDB` 或 `default_storage_engine` |
| 对应文件 | `docs/lessons/11-MySQL存储引擎与执行计划.md` |

## 七、重要知识点速查

1. **SQLite → MySQL 的 4 处改动**：脚本建表、连服务而非连文件、`?` → `%s`、`row[0]` → `row["name"]`（DictCursor）。
2. **中文乱码排查法**：先 `select hex(name)` 看底层字节，再对比 UTF-8 编码，确认是数据问题还是终端显示问题——不要盲改配置。
3. **InnoDB vs MyISAM**：事务、外键、行锁、崩溃恢复；MyISAM 对比实验里回滚无效、外键静默忽略。
4. **EXPLAIN 四字段**：`type`（访问方式）、`key`（用的索引）、`rows`（估算扫描行数）、`Extra`（是否覆盖索引 / 临时表 / 文件排序）。
5. **B+ 树与聚簇索引**：页 16K，叶子存整行，主键查询最快；二级索引要回表。
6. **主从复制链路**：binlog → IO 线程 → relay log → SQL 线程重放；`read_only` 防误写。
7. **Nginx 两件事**：`upstream` 定义后端列表，`proxy_pass` 转发；默认轮询。
8. **分片上传**：切分 → 逐片传 → 按序号重组；对应 OSS multipart upload。
9. **RBAC**：用户 → 角色 → 权限，两张关联表；鉴权是一条 join。
10. **统一响应 + 模块拆分**：公共类只抽象"稳定且复用"的部分；按变化理由拆文件。

### 7. 文件传输增强（2026-10-27）

在原有分片上传之上补齐了可演示的断点续传与进度条：

| 能力 | 实现 |
|---|---|
| 上传断点续传 | `GET /api/upload/status/{file_id}` 返回 `uploaded` / `missing`，前端只补缺失分片 |
| 上传进度条 | `XMLHttpRequest.upload.onprogress`，整体进度 = 已完成字节 + 当前片已传字节 |
| 下载断点续传 | `GET /api/upload/download/{filename}` 解析 `Range`，返回 `206 Partial Content` |
| 下载进度条 | `fetch` + `ReadableStream`，按块累加 `downloadedBytes` |
| 小文件批量上传 | `POST /api/upload/batch` 一次收多个文件，前端 `UploadLab.vue::uploadBatch` |
| 前端演示页 | 左侧 **07 上传实验**：20MB 演示文件、暂停/继续、分片状态、日志、5 个小文件批量上传 |
| 文档 | `docs/原理-上传下载断点续传.md`、`docs/lessons/22-断点续传与进度条.md`、`docs/演示脚本-上传下载断点续传.md` |

实测：20MB / 20 片，上传暂停在 20%（4 片）后继续，只补 16 片；下载暂停在 25%（4.9MB）后继续，最终 100%，可保存文件。
