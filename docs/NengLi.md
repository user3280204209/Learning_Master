# 能力地图与学习方法

> 使用说明：上半部分是**你要补齐的能力全貌**，用来对照检查自己走到哪了；
> 下半部分是**学习节奏和规则**，每次想"我该先学什么"的时候回来重读一遍。

---

## 一、能力地图

这是补齐这个项目所需能力的全貌。**不用一次学完，遇到什么补什么。**

| 层级 | 要掌握的能力 | 在这个项目里对应什么 |
|---|---|---|
| **L0 地基** | Python 工程化（虚拟环境 / 模块 / 类型注解 / 异常 / 日志）、命令行、Git、读懂报错信息 | 贯穿所有代码，不补会一直还债 |
| **L1 后端** | HTTP 与 REST 概念、FastAPI（路由 / 请求响应模型 / 数据校验）、SQL 与表设计、ORM、接口设计 | 画像服务、资源服务、路径服务 |
| **L2 前端** | HTML / CSS / JS 够用即可、Vue 3（组件 / 状态 / 请求）、前后端联调 | 对话界面、画像可视化、资源展示 |
| **L3 AI 工程** | LLM API 调用、Prompt 设计、结构化输出、上下文与成本控制、失败重试与降级、RAG 检索、Agent 编排与状态传递 | 画像抽取、资源生成、路径规划 |
| **L4 工程素养** | 调试方法论、日志、测试、代码组织、文档表达、协作 | **决定你是"能写代码"还是"能交付系统"** |

### 各层说明

**L0 地基**
最枯燥但最不能跳。新手写不出能跑的系统，通常不是不懂算法，而是不懂虚拟环境、模块导入、异常处理、日志这些"语法书不教但必须会"的东西。这一层不补，后面每写一行代码都在还债。

**L1 后端**
这是面试问得最多的一层，也最容易讲出深度。重点不是会用框架，而是理解：一个请求从进入到返回，中间经过了什么。

**L2 前端**
目标是"够用"。会调接口、会渲染列表、会做基本交互就行。不用深究样式和性能——把省下的时间投给 L1 和 L3。

**L3 AI 工程**
这是你最想深入的方向，建议从第一天就开始接触，不要等"基础打牢"。它和传统后端最大的区别是：**模型输出是不确定的**，所以重试、校验、降级这些"处理不确定性"的能力是这一层的核心。

**L4 工程素养**
自学者最容易忽略，但**实习面试区分度最大**。因为"会写代码"的人很多，能定位问题、能讲清楚设计权衡的人很少。这个项目最大的价值恰恰在 L4——技术方案会过时，调试和表达能力不会。

## 二、学习方法：项目为纲 + 三层循环

### 核心原则

> **不要"先学完再做"。那样你会永远停在教程第二章。**

要以项目为纲——需要什么补什么，但**每个知识点都必须落到项目里的真实代码上**。看十遍教程不如让一个接口真的跑起来。

### 三层循环

| 循环 | 周期 | 做什么 |
|---|---|---|
| **微循环** | 每次 1～2 小时 | 完成一个小任务。例如"让某个接口返回一个假的画像 JSON" |
| **中循环** | 每周 | 完成一个完整功能 + 一次代码 review |
| **大循环** | 每两周 | 写一次复盘：做了什么 / 卡在哪 / 下次怎么改 |

判断标准很简单：**每次坐下，都要以"有一个能跑的东西"结束。** 如果两个小时过去了只是"看懂了"，但没有一行代码跑起来，这次学习是不合格的。

### 学习日志（强烈建议从现在开始）

每次卡住，记下这四行：

```
日期：
现象：我遇到了什么
假设：我猜是什么原因
真正原因：
下次怎么更快定位：
```

**为什么值得记**：三个月后这份日志就是你的面试弹药库。面试官问"你遇到过什么困难怎么解决的"，有日志的人能讲出具体细节，没日志的人只能讲套话。这比任何简历项目描述都管用。

### 一个心态提醒

新手的自我怀疑通常来自**错误的进度参照**。你会觉得"我怎么这么慢"——那个速度是正常的。判断自己有没有进步，不要和"想象中的高手"比，要和自己两周前比：**两周前你看不懂的报错，现在能不能看懂了。**

---

## 三、三条纪律

1. **不许复制粘贴代码。** 手敲才能形成肌肉记忆，也才能记住。报错了我们一起看。
2. **不许跳层。** 尤其别跳过 L0。地基不补，后面每写一行代码都在还债。
3. **不许无限期拖延。** 没有硬截止日期最大的风险不是时间不够，而是"反正不急"。给自己定一个软截止并写进日历——例如"3 个月内必须能跑通全流程"。
