 第 0 步：立项与范围界定（1～2 天）
  先确定边界，否则后面全是返工：
  - 团队分工：这个项目天然适合分 4 块——画像 / 多智能体生成 / 路径推送 / 加分项 + 文档负责人。
  - 技术选型：建议 Python + FastAPI 后端，React 或 Vue 前端，LLM 走 Claude API，向量库用 Chroma（本地轻量），数据库
    PostgreSQL 或 SQLite。
  - 确定 MVP 范围：需求 1～3 是必做，4、5 是加分。一定要先约定"时间不够时砍哪个"，答案是先砍 4、5。

  第 1 步：需求分析（软件工程课的硬性交付物）
  产出 《需求规格说明书 SRS》 + 用例图 + 用例描述表：
  - 把 5 条功能需求拆成具体用例（如"学生通过多轮对话完成画像构建"、"系统生成思维导图资源"），每条写清前置条件、主流程、
    异常流程。
  - 提炼非功能需求：响应时间、并发、数据隐私（学生画像属敏感数据）、可用性。这一条很多人漏掉，是扣分点。
  - 明确角色：学生 / 教师（可选）/ 各智能体。

  第 2 步：系统架构设计（这个项目的核心亮点，必须做扎实）
  产出概要设计文档 + UML 图（架构图、类图、关键时序图、状态图、部署图）：
  - 多智能体架构是评分主线。建议设计成 Orchestrator（总控）+ 专职 Agent 群：
    - 画像抽取 Agent、讲解文档 Agent、思维导图 Agent、出题 Agent、拓展阅读 Agent、多模态视频/动画 Agent、代码实操
      Agent、路径规划 Agent、评估 Agent。
  - 关键设计决策（决定系统是否真"动态"）：
    - 画像作为共享黑板（Blackboard）：所有 Agent 从画像读需求、把结果写回画像，而不是各 Agent 各存一份。
    - 闭环：评估结果 → 更新画像 → 重算学习路径 →
      调整推送，这条闭环是需求里"随学随新"和"动态优化"的技术落点，一定要在架构图上画出来。
  - 定义 Agent 间通信协议、任务编排方式（串行/并行/DAG）、失败重试与降级。

  第 3 步：数据库与接口设计
  - 表：学生、画像维度（≥6 维）、对话记录、资源、学习路径、学习行为/评估数据。
  - 先冻结接口契约（RESTful API 文档），前后端和多智能体才能并行开发。

  第 4 步：搭建骨架（Walking Skeleton）
  端到端跑通一条最细的线：前端输入一句话 → 后端调 LLM → 返回一个结果并展示。别等所有功能做完才联调。

  第 5 步：按依赖顺序迭代开发核心模块
  顺序不能乱，因为后者依赖前者：
  1. 对话式画像构建（需求 1）——它是其他一切的数据来源，必须最先做。
  2. 多智能体编排框架 + ≥5 种资源生成（需求 2）——先做 2 种跑通编排，再横向扩到 5 种以上。
  3. 学习路径规划 + 精准推送（需求 3）——依赖前两者的产出。
  4. 智能辅导（需求 4，加分）。
  5. 学习效果评估 + 反馈闭环（需求 5，加分）——它要回头改进第 1 步的画像，所以放最后。

  第 6 步：测试与验证
  单元测试 → 集成测试 → 系统测试 →
  用户验收。多智能体系统额外要有生成质量评估（资源是否真的贴合画像、路径是否合理），建议做人工打分表 + 对比实验（有画像
  vs 无画像）。

  第 7 步：文档汇总、演示、答辩
  演示视频 + PPT，重点讲架构决策和闭环设计，而不是逐个功能念一遍。

  ---

  一句话总结顺序

  ▎ 立项 → 需求分析(SRS) → 架构设计(多智能体+画像黑板) → 库表与接口 → 骨架跑通 → 画像 → 资源生成 → 路径推送 → 加分项 →
  ▎ 测试 → 文档答辩

  贯穿全程：每周一次迭代、Git 分支管理、持续维护过程文档（软件工程课很看重过程留痕）
