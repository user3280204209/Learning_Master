# 2 分钟演示脚本（初学者简化版）

> **页面**：<http://127.0.0.1:8001/#upload>
> **原则**：不背行号、不讲细节，只讲“哪个文件负责什么”。
> **详细原理**：`docs/原理-上传下载断点续传.md`（老师追问时再看）

---

## 一、只记住 4 个文件

| 文件 | 一句话作用 |
|---|---|
| `frontend/src/components/UploadLab.vue` | 上传实验页面：切片、进度条、暂停/继续 |
| `frontend/src/api.js` | 前端请求封装：拼出 `/api/upload/...` 地址 |
| `backend/routers/upload.py` | 后端四个接口：收分片、查进度、合并、下载 |
| `backend/main.py` | 给所有接口加统一前缀 `/api` |

后端 `upload.py` 里也只有四个函数：

| 函数 | 作用 |
|---|---|
| `upload_chunk` | 收一个分片，存到 `uploads/{file_id}/序号` |
| `upload_status` | 告诉前端：哪些分片已经收到、哪些还缺 |
| `complete_upload` | 把所有分片按顺序拼成完整文件 |
| `download` | 按 `Range` 只返回文件的一部分，支持断点下载 |
| `upload_batch` | 一次请求收多个小文件，循环落盘 |

| **1:10–1:25** | 点 **「开始下载」**，到 25% 点 **「暂停下载」**。 | 切 `frontend/src/components/UploadLab.vue`，指一下 `startDownload`。 | “下载到 25% 暂停，已经收到的字节保留；继续时从 4.9MB 这个位置接着下，不从头来。” |
| **1:25–1:40** | 点 **「继续下载」**，等到 100%，指日志里的 `Range: bytes=...`。 | 切 `backend/routers/upload.py`，指一下 `download`。 | “后端 `download` 收到 `Range` 后只返回剩下的部分，所以叫断点续传。” |
| **1:40–1:55** | 点 **「保存文件」**，切回页面。 | 切 `frontend/src/api.js`，指一下 `uploadStatus` 和 `uploadDownloadUrl`。 | “前端所有请求都走 `api.js`，由它拼成 `/api/upload/...`；`/api` 前缀是 `main.py` 统一加的。” |
| **1:55–2:00** | 停在 100% 的页面和日志。 | 不切。 | “总结：上传断点靠‘查已传分片’，下载断点靠 `Range`，进度条靠真实字节。” |

> 代码切屏最多停 5–8 秒，指一下函数名就切回页面，不要展开讲参数和行号。

## 五、老师可能追问的三个问题

| 问题 | 一句话回答 |
|---|---|
| 断点续传是不是重传整个文件？ | 不是，只补服务端缺少的分片。 |
| 进度条是假的吗？ | 不是，上传用浏览器真实的上传字节事件，下载用真实读到的字节数。 |
| 下载为什么能接着下？ | 因为 HTTP 支持 `Range`，服务端返回 `206 Partial Content`，只给剩余部分。 |
| 小文件为什么批量传？ | 小文件瓶颈是数量和连接次数，一次请求带多个文件可以减少往返；大文件仍走分片。 |

## 六、加时 40 秒：小文件批量上传（老师问到时再演示）

页面往下滚到第三块 **3. 小文件批量上传**。

| 时间 | 页面点击 | 切到 VS Code 看什么 | 口播 |
|---|---|---|---|
| **0:00–0:08** | 点 **「使用 5 个小文件演示」**；鼠标指 5 个文件列表和 `915.0 KB`。 | 不切。 | “小文件不适合一片一片传，这里一次选 5 个，放在同一个请求里批量上传。” |
| **0:08–0:20** | 点 **「开始批量上传」**，让整体进度到 100%。 | 切 `frontend/src/components/UploadLab.vue`，指一下 `uploadBatch`。 | “这个函数把 5 个文件都 append 到同一个 `FormData`，只发一次 `POST /api/upload/batch`。” |
| **0:20–0:30** | 指 5/5、每个文件的「完成 / 下载」。 | 切 `backend/routers/upload.py`，指一下 `upload_batch`。 | “后端 `upload_batch` 循环把每个小文件落盘，返回文件列表；这就是批量上传。” |
| **0:30–0:40** | 指一下上方分片上传卡片。 | 不切。 | “小文件用批量，大文件用分片；分片能断点续传，批量只适合数量多、单个小的文件。” |

> 小文件批量上传**没有单文件进度和断点续传**，一个 XHR 只有整体进度；失败通常整批重来。这是它的边界。

## 七、别讲这些（初学者容易讲乱）

- 不要背 `Range` 正则、`Content-Range` 解析细节；
- 不要讲 MD5、并发、临时文件清理；
- 不要逐行读代码，只指函数名和作用；
- 不要解释 `file_id` 的 UUID 生成，除非老师问。
