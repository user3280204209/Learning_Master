# 立项会材料

> 目标：60 分钟，产出 **6 个决定** + **1 份纪要**
> 纪律：严格控时。项目细节讨论留到会后，今天只做决策。

---

## 一、议程

| 时间段 | 内容 | 产出 |
|---|---|---|
| 0–5 min | 对齐需求边界 | 确认必做/可选项 |
| 5–25 min | **技术栈决策** | 一张技术栈表 |
| 25–40 min | **分工** | 一张分工表 |
| 40–45 min | 时间预算 | 每人每周可投入小时数 |
| 45–55 min | 协作规则 | Git 流程 / 例会 / 沟通渠道 |
| 55–60 min | 风险预案 + 下周任务 | 任务清单 |

## 二、需要拍板的 6 件事

### 决定 1：技术栈（最重要，20 分钟）

**制定原则：顺着组里「已经会的」选，不要为了"先进"去学新东西。** 一个半月不够同时学新语言 + 做项目。

| 层次 | 建议方案 | 备选 | 理由 |
|---|---|---|---|
| 后端 | Python + FastAPI | Node/Express、Java Spring Boot | LLM 生态最完整，代码量少 |
| 前端 | Vue 3 | React | 模板语法直观，新手平缓 |
| 数据库 | SQLite（起步） | MySQL、PostgreSQL | 零配置，一个文件就能跑 |
| 大模型 | Claude API | 国内模型（通义/DeepSeek 等） | 能力最强，但**需提前确认能否拿到 key 和预算** |
| 向量库 | Chroma | Milvus、pgvector | 本地运行，零配置 |
| 智能体编排 | **先手写最小版，再换 LangGraph** | CrewAI、AutoGen | 先理解原理，再上框架 |

> ⚠️ 上表是**我的建议**，不是标准答案。如果组里有人很熟 Java，就该用 Java——熟练度比技术先进性重要得多。

### 决定 2：项目范围（5 分钟）

- **必做**：需求 1（对话式画像）、需求 2（≥5 种资源生成）、需求 3（路径规划与推送）
- **加分项**：需求 4（智能辅导）、需求 5（效果评估）——**今天先不做**，W5 看进度再决定
- 明确一句话：**时间不够时，先砍加分项，再砍前端美观度，绝不砍必做三条**

### 决定 3：分工（15 分钟）

| 成员 | 负责模块 | 说明 |
|---|---|---|
| A | 对话式画像构建（后端） | 全链路数据源头，能覆盖各层技术 |
| B | 多智能体编排框架 | **全组最难的一块，B 同时担任技术负责人** |
| C | ≥5 种资源生成 Agent + 工具集成 | 数量多但模式重复，可复制 |
| D | 前端全流程 | 画像可视化、资源展示、路径展示 |
| 全员 | 文档轮值 | 每人负责一段，别让一人写全部 |

**分工原则**：时间最少的人 → 分「边界最清楚、最少依赖别人」的模块（如前端页面）。

### 决定 4：时间预算（5 分钟）

每人当场回答：

1. 我每周能投入几小时？（**要诚实，大三还有别的课**）
2. 这一个半月里有没有别的项目/考试撞期？

> **判断线**：如果每人每周平均 < 8 小时，加分项直接放弃，必做三条也要再收窄。

### 决定 5：协作规则（10 分钟）

**Git 流程（今天定，明天就执行）**
- `main` 分支保护，**任何人不得直接推送**
- 每人开自己的 feature 分支开发
- 完成后提 PR，**至少 1 人 review 通过才合并**
- 禁止用微信/QQ 传代码文件

**例会**
- 每周固定时间（建议周日晚 20:00），**30 分钟**
- 只讲三件事：上周做了什么 / 卡在哪 / 下周做什么
- 不讨论技术细节，细节另约

**沟通**
- 日常沟通用群聊
- **任务和 bug 用 GitHub Issues**，不要只留在聊天记录里
- 设计文档放仓库 `docs/` 目录，用 Markdown，纳入版本管理

### 决定 6：风险预案（5 分钟）

| 风险 | 应对 |
|---|---|
| 某成员连续两周没有产出 | 组长在 W3 前介入沟通，**不要拖到 W5** |
| 技术方案卡壳超过 1 天 | 立即换方案降级，不钻牛角尖 |
| 大模型 API 用不了 / 超预算 | 立刻切换备用模型，**W1 就要验证** |
| 进度落后一周以上 | 按决定 2 的顺序砍功能，不要拖交期 |

## 三、会前必须提前确认的 3 件事

> 这三件事不解决，会议开了也是白开。

1. **大模型 API 能不能用**：能拿到 key 吗？有预算吗？网络能访问吗？
   → 这是整个项目的命脉，W4 才发现会直接崩盘，**今天就要验证**
2. **每人真实可投入的时间**：会前各自想好数字，会上直接报
3. **组里每个人「实际会什么」**：注意是**会**，不是**想学**。这决定技术栈怎么选

## 五、会后你要发给我的

把上面那份纪要发我，我会帮你检查三件事：

1. **分工有没有埋雷**（比如两个模块互相强依赖，却分给沟通不畅的两个人）
