## 一、为什么不要人肉记规则

你的代码里有这几处：

```python
major:str            # 冒号后少空格
goal: str ="未填写"    # 等号前多空格
"profile":{          # 冒号后少空格
f"这是..."            # f-string 里没有占位符，f 是多余的
```

这些都违反 **PEP 8**（Python 官方代码风格）。但你要学的**不是背这些规则**——

> **不要人肉记风格规则，交给工具。**

理由有三：

1. **规则太多记不住**，而且各家团队还有自己的偏好
2. **人肉检查不可靠**，你写代码时注意力在逻辑上，不在空格上
3. **实习时会有 lint 检查**，格式不规范的 PR 会被打回。与其那时候被说，不如现在就自动化

## 二、Ruff 是什么

**Ruff** 是目前 Python 生态里最流行的代码检查工具，由 Astral 公司用 Rust 写成，特点是**极快**。

它一个工具干两件事，**这两个概念要分清**：

| 命令 | 干什么 | 类比 |
|---|---|---|
| `ruff format` | 只管**格式**——空格、缩进、换行、引号 | 排版 |
| `ruff check` | 找**问题**——未使用的变量、多余的 f-string、可疑写法 | 审查 |

`ruff check --fix` 可以自动修掉一部分能修的问题。

> **为什么用 Ruff 而不是别的？** 以前 Python 要装一堆工具（black 管格式、flake8 管检查、isort 管导入排序），Ruff 把它们的活全包了，而且快几十倍。**新项目基本都直接上 Ruff。**

## 四、关键习惯：用 `git diff` 看工具改了什么

`git diff` 会逐行显示"改之前 / 改之后"：

- **绿色 `+`** 开头的行 = 新增的
- **红色 `-`** 开头的行 = 删掉的

**养成习惯**：任何工具自动改了你的文件之后，都 `git diff` 看一眼。

> 这不是不信任工具，而是**你要知道发生了什么**。实习 review 代码时，你说得出"这里被 formatter 改了"和说不出，是完全两回事。

如果看完觉得不对，想全部退回：
```bash
git checkout .      # 丢弃所有未提交的改动，回到上次提交的状态
```

## 五、配 VS Code：保存自动格式化

上面是命令行手动跑。**真正的效率提升在编辑器里**——保存时自动格式化，你就不用管了。

### 5.1 装扩展

VS Code 左侧「扩展」面板（`Ctrl+Shift+X`），搜索 **Ruff**，发布者是 **Astral Software**，装它。

### 5.2 选中虚拟环境（重要，别跳）

`Ctrl+Shift+P` → 输入 `Python: Select Interpreter` → 选中：

```
./backend/.venv/Scripts/python.exe
```

**为什么这步重要**：VS Code 得知道"这个项目用哪个 Python"，才能找到你装的包。**不选这个，后面一堆东西都用不了。**

### 5.3 配置保存时自动格式化

打开 `.vscode/settings.json`（在 **Learning/** 根目录下），改成：

```json
{
    "python.analysis.autoImportCompletions": false,
    "[python]": {
        "editor.formatOnSave": true,
        "editor.defaultFormatter": "charliermarsh.ruff",
        "editor.codeActionsOnSave": {
            "source.fixAll": "explicit",
            "source.organizeImports": "explicit"
        }
    }
}
```

**逐项解释**：

| 配置 | 作用 |
|---|---|
| `editor.formatOnSave` | 保存时自动排版 |
| `editor.defaultFormatter` | 用 Ruff 来排版 |
| `source.fixAll` | 保存时自动修掉能修的问题（比如多余的 `f`） |
| `source.organizeImports` | 保存时自动给 import 排序、删除没用的 import |

> ⚠️ **注意是合并，不是覆盖**——你原来的 `python.analysis.autoImportCompletions` 要保留。

## 六、依赖管理：把要装的东西写下来

现在有个问题：你装了 `fastapi`、`uvicorn`、`ruff`，但这些只存在于**你这台电脑的 `.venv` 里**。组员 clone 你的仓库后，怎么知道要装什么？

**答案：写一个 `requirements.txt`。**

在 `backend/` 下新建：

```
fastapi
uvicorn[standard]
ruff
```

别人拿到后，一条命令就能装齐：

```bash
pip install -r requirements.txt
```

> **这就回答了第一课那个问题**——为什么 `.venv` 不进版本控制？
> 因为它能靠 `requirements.txt` **一条命令重建**。
> **能重建的东西就不提交**，这是版本控制的核心原则。
