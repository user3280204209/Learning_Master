# 第 12 课：数据库读写分离（MySQL 主从复制）

> **日期**：2026-10-26
> **目标**：本机搭 MySQL 主从两实例，验证"主库写、从库读"的读写分离

---

## 一、读写分离是什么、为什么

**读和写分开**：写（insert/update/delete）走主库，读（select）走从库。

**为什么要分开**：大多数系统的读写比例是 9:1（读远多于写）。一台库扛不住海量读时，把读压力分摊到多台从库，写只留给主库——**水平扩展读能力**。

> 实现分两层：
> 1. **数据层**：主从复制（本课做的）——主库的改动自动同步到从库
> 2. **应用层**：代码里"写走主、读走从"的路由（后面公共模块抽象时可以做）

---

## 二、主从复制的原理（一句话）

主库把每一次写操作记录到 **binlog**（二进制日志），从库的 IO 线程拉取 binlog、SQL 线程重放——所以从库变成了主库的"副本"。

```
主库写 → binlog → 从库 IO 线程拉取 → 从库 SQL 线程重放 → 从库数据 = 主库数据
```

## 三、搭建过程（真实命令，本机 3306 主 / 3307 从）

```ini
# 主库 my.ini 加三行（binlog 是复制的源头）
server-id=1
log-bin=mysql-bin
binlog_format=ROW
```

```bash
# 1. 初始化从库独立数据目录
mysqld --initialize-insecure --datadir=.../data-slave

# 2. 从库用不同端口 + 不同 server-id 启动
mysqld --datadir=.../data-slave --port=3307 --server-id=2

# 3. 主库建复制账号
CREATE USER 'repl'@'%' IDENTIFIED BY 'repl123456';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%';

# 4. 导出主库数据 + 记录 binlog 位置
mysqldump --single-transaction --master-data=2 --databases learning > dump.sql

# 5. 从库导入
mysql --port=3307 < dump.sql

# 6. 从库配置复制并启动
CHANGE MASTER TO MASTER_HOST='127.0.0.1', MASTER_PORT=3306,
  MASTER_USER='repl', MASTER_PASSWORD='repl123456',
  MASTER_LOG_FILE='mysql-bin.000001', MASTER_LOG_POS=1652;
START SLAVE;

# 7. 从库设为只读
SET GLOBAL read_only=1;
```

**验证结果**：主库 insert → 从库 2 秒内读到，`Slave_IO_Running=Yes`、`Slave_SQL_Running=Yes`。

## 四、踩到的两个坑（都是 MySQL 8 的经典坑）

### 坑 1：复制账号认证失败（错误 2061）

```
Authentication plugin 'caching_sha2_password' reported error:
Authentication requires secure connection.
```

**原因**：MySQL 8 默认认证插件 `caching_sha2_password` 要求安全连接，复制 IO 线程连不上。

**解决**：把复制账号改成旧的 `mysql_native_password` 认证：

```sql
ALTER USER 'repl'@'%' IDENTIFIED WITH mysql_native_password BY 'repl123456';
```

### 坑 2：mysqldump 的警告混进 dump 文件

现象：`mysqldump ... > dump.sql 2>&1` 后，`mysql < dump.sql` 报 `ERROR 1064`。

**原因**：mysqldump 的 `Using a password...`（stderr）和 `--master-data is deprecated`（**stdout**）两个警告被写进了 dump 文件，第一行不是 SQL。

**解决**：stderr 丢弃 + stdout 过滤警告行：

```bash
mysqldump ... 2>/dev/null | grep -v "^WARNING" > dump.sql
```

> **方法论**：重定向命令的输出到文件时，永远要想清楚"stdout 和 stderr 各自去哪了"。`2>&1` 把它们合并，反而常常带来麻烦。

## 五、应用层怎么配合（下一步）

数据层通了，但"读写分离"要真正生效，还得代码配合——**写操作连主库（3306），读操作连从库（3307）**。

两种做法：
1. **简单版**：`db.py` 里定义两个连接（`get_master_db()` / `get_slave_db()`），接口里按读写选择
2. **中间件版**：MyCat / ShardingSphere 在中间做路由（生产环境用，学习先不用）

这个可以放到"公共模块抽象"那一步一起做。
