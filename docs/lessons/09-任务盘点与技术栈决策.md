## 二、一个必须先说清楚的问题：大纲是 Java 栈写的

老师这份"分块一/二/三"里，好几条是 **Java 生态的专属名词**。直接照做会撞墙，因为它们压根不适用于你现在的项目：

| 大纲里的词 | 是什么 | 对你项目意味着什么 |
|---|---|---|
| **Tomcat** | Java 的 Servlet 容器（跑 Java Web 的服务器） | 你用的是 FastAPI，**不能部署到 Tomcat 上** |
| **MySQL 存储引擎（InnoDB/MyISAM）** | MySQL 内部的两种表存储方式 | SQLite 是单文件数据库，**没有引擎这个概念** |
| **MySQL 读写分离（主从）** | 一台写、多台读，分摊压力 | SQLite 是单文件，**天然做不了** |
| **禅道** | 国产开源项目管理工具（PHP + MySQL） | 这条是**独立练习**，跟你的主项目无关 |

**这些条目不是"改个参数"就能做，而是要换数据库、或者换服务器。** 所以第一件事不是动手，是**想清楚这些要求怎么落到你的项目上**。

### Java 术语 → Python 栈的等价物

如果老师允许"用等价技术实现"（通常允许，因为你已经用 Python 立项了），对照关系是这样的：

| 大纲要求 | 你在 Python 栈里应该做 |
|---|---|
| Tomcat 配置 | **uvicorn**（你现在就在用）+ **gunicorn**（多进程）+ **Nginx**（反向代理） |
| Tomcat 集群 | 多个 uvicorn/gunicorn worker，Nginx 做负载均衡 |
| MySQL 读写分离 | **把 SQLite 换成 MySQL**，做主从复制，代码里读走从库、写走主库 |
| MySQL 执行计划 | MySQL 的 `EXPLAIN`（用上一步换来的 MySQL 演示） |
| MySQL 存储引擎 | InnoDB vs MyISAM 的配置对比（同样用 MySQL 演示） |

> 注意：**Nginx 是通用的**，不管 Java 还是 Python 都拿它做反向代理和负载均衡。所以"分块一.3"里真正属于 Python 的部分是 **Nginx + uvicorn/gunicorn**，Tomcat 那部分你替换掉即可。

## 三、两条路线，各自代价（我不替你选，你来权衡）

### 路线 A：主项目换成 MySQL，其余保持 Python

- **怎么做**：`db.py` 从 `sqlite3` 换成 MySQL 驱动（如 `pymysql` / SQLAlchemy），装上 MySQL，把读写分离、执行计划、存储引擎这些要求**在真实 MySQL 上做**。
- **好处**：分块一.4、分块二几乎全部能真做，课程覆盖度最高；MySQL 也是面试必问，顺便补上了。
- **代价**：要装 MySQL 服务、要改连接代码、要多学 MySQL 特有的东西；SQLite 的"零配置"优势没了。

### 路线 B：SQLite 继续做主库，MySQL 相关单独起一个"演示/学习"项目

- **怎么做**：主项目保持 SQLite 轻量开发；读写分离、执行计划、存储引擎这些 MySQL 特性，**单独开一个小项目/笔记**去演示和理解。
- **好处**：主项目不被数据库迁移拖慢；MySQL 那些是"了解 + 能演示"即可，不必绑进主业务。
- **代价**：课程要求是"落在你的项目里"，单独演示可能被老师问"为什么主项目里没有"。

> ⚠️ 有一条你必须**先问老师**：分块一.3 明确写了"做 Tomcat 集群"。
> 如果你已经用 Python 立项并且老师认可，这条大概率可以**等价替换成 Nginx + uvicorn**；
> 但如果老师坚持要看 Tomcat，那可能意味着这个项目要**部分或全部改回 Java 栈**——这是一个会影响后面所有进度的决定，**别自己猜，去确认。**

## 四、不管选哪条，执行顺序是固定的

有些任务有依赖关系，顺序不能乱：

```
① 数据建模（ER 图，用建模工具）   ← 分块二.3/二.4，分块三.3 的前置
        │
② 物理建表 + 持久化              ← 分块三.3，现在已有雏形，缺"建模工具"这一步
        │
③ 数据库换成 MySQL（若选路线 A）  ← 分块一.4、二.1、二.2 的前置
        │
④ 读写分离 / 执行计划 / 存储引擎   ← 分块一.4、二.1、二.2
        │
⑤ 服务器配置 + Nginx + 负载均衡   ← 分块一.3，可以单独做，不依赖数据库
        │
⑥ 公共模块抽象 / 拆分             ← 分块一.1，贯穿全程，量大了自然要拆
        │
⑦ 大文件分片 / OSS / 小文件读写   ← 分块三.2，独立于数据库，可并行
        │
⑧ 禅道 RBAC 分析                 ← 分块三.1，纯独立练习，随时可做
```

**接口文档（分块三.4）已经天然具备**（FastAPI `/docs`），你只需要知道"怎么把 Swagger 的配置补齐、怎么导出"即可，不用额外开发。

## 八、决策后的下一步（顺序）

```
① 装环境：MySQL + 建模工具（建议 MySQL Workbench，一个工具同时覆盖"建模"和"连 MySQL"）
② 画 ER 图：先想清楚系统要哪些实体（画像维度、对话、资源、路径、评估…），再落笔

⑥ Nginx + 多 worker 负载均衡（分块一.3）

```

**注意：② 的建模是换 MySQL 之前就该做的**——不然你换库的时候手里没有一套像样的表结构，等于白换。
