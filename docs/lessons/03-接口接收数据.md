# 第 3 课：让接口能"接收数据"

> **日期**：2026-10-13
> **前置**：第 2 课（Git 版本控制）
> **目标**：让 FastAPI 接口能接收参数和请求体——这是写项目里每一个接口的基础

---

## 一、为什么这是分界线

你现在的接口**谁访问都一样**，返回固定的字符串。但真实系统里，接口必须接收用户给的数据。

在你的项目里就是：**学生说了一句话 → 这句话怎么传到后端？**

这是从"能跑"到"有用"的分界线。学完这一课，你就具备了写项目里每一个接口的能力。

---

## 二、三种传数据的方式

由简到繁，**第三种是真实项目的主力**：

| 方式 | 长相 | 用在哪 |
|---|---|---|
| **路径参数** | `/hello/张三` | 数据直接嵌在路径里，比如 `/profile/123` 取某人的画像 |
| **查询参数** | `/hello?name=张三` | 跟在 `?` 后面，常用于筛选、分页 |
| **请求体** | `POST` + JSON | **项目里 90% 的接口都是这个** |

## 三、动手：改 `main.py`

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class ProfileRequest(BaseModel):
    name: str
    major: str
    goal: str = "未填写"

@app.get("/")
def read_root():
    return {"message": "我的第一个 FastAPI 应用程序!"}

@app.get("/hello/{name}")
def say_hello(name: str):
    return {"message": f"你好，{name}"}

@app.post("/profile")
def create_profile(req: ProfileRequest):
    return {
        "student": req.name,
        "profile": {
            "专业": req.major,
            "学习目标": req.goal,
        }
    }
```

## 四、逐段讲解

### 4.1 路径参数

```python
@app.get("/hello/{name}")
def say_hello(name: str):
```

URL 里的 `{name}` 是个**占位符**。访问 `/hello/张三` 时，FastAPI 会自动把 `张三` 取出来传给你的函数。

**关键点**：函数参数上写了 `: str`，FastAPI 就会保证传进来的**一定是字符串**。

> 这就是"类型注解"在 FastAPI 里的第一个威力——**它不是给人看的注释，是给框架用的说明书。**

### 4.2 请求体 + Pydantic（重点）

```python
class ProfileRequest(BaseModel):
    name: str
    major: str
    goal: str = "未填写"
```

这个类描述了"我期望收到的 JSON 长什么样"。`BaseModel` 来自 **Pydantic**（FastAPI 自带的，不用单独装）。

**为什么必须要有这个东西？**

因为**进来的数据不可信**。用户可能少传字段、传错类型、传个空值。你不可能在每个函数里写一堆 `if` 去检查。Pydantic 帮你做了这件事：

- 字段名对不上 → 自动报错
- 类型不对（比如 `name` 传了数字）→ 自动报错
- 有默认值的字段可以省略 → `goal` 就是

> **这是你项目里极重要的一环**：以后你要让大模型把学生的自然语言抽成结构化画像，用的**就是同一套东西**——先用 Pydantic 定义好画像的结构，再去要求模型按这个结构输出。
> **今天学的是地基，几周后直接复用。**

## 七、补充：422 是什么（练习 1 的答案）

**422 Unprocessable Content** —— 意思是"请求的**格式**没问题，但**内容**不合法"。

在你的实验里：JSON 格式是对的，但 `name` 字段你给了 `123`（数字），而代码里声明的是 `str`（字符串）→ 校验失败。

### 7.1 最关键的一点：函数压根没执行

`create_profile()` 函数**一次都没有被调用**。

Pydantic 在请求进入你的函数**之前**就把它拦下来了。你只写了一句 `name: str`，框架就帮你挡住了所有脏数据——**这就是"声明式校验"的威力**：

> 你声明"我要什么"，框架负责"挡住了什么"。你不用写一行 `if` 判断。

### 7.2 去 `/docs` 展开 response body（精华在这里）

返回的 JSON 里有一个 `detail` 字段，它会**精确告诉你哪里错了**：

```json
{
  "detail": [
    {
      "type": "string_type",
      "loc": ["body", "name"],
      "msg": "Input should be a valid string"
    }
  ]
}
```

- `loc` = 出错的位置（`body` 里的 `name` 字段）
- `msg` = 原因

**这就是为什么要用 Pydantic**：出错时不用你自己猜是哪个字段，它全告诉你了。以后你调大模型、调别人的接口，看到 422 就照着 `loc` 改。

### 7.3 HTTP 状态码速查

| 码 | 含义 | 谁的锅 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 请求格式有错 | 调用方 |
| 401 | 没有凭证（未登录） | 调用方 |
| 403 | 有凭证但没权限 | 调用方 |
| 404 | 资源不存在 | 调用方 |
| **422** | **格式对，内容不合法（校验失败）** | **调用方** |
| 500 | 服务器内部出错 | **服务端** |

> **只需要记住一条规律**：**4xx 是调用方的问题，5xx 是服务端的问题。**
> 这一条能让你一眼判断"该改我的代码，还是该找对方"。

## 八、补充：curl 是什么（练习 2 的答案）

`curl` 是一个**命令行下的 HTTP 客户端**——不用浏览器，也能发请求。

`/docs` 页面上给你的那段，就是**调用这个接口的一条完整命令**：

```bash
curl -X 'POST' \
  'http://127.0.0.1:8001/profile' \
  -H 'accept: */*' \
  -H 'Content-Type: application/json' \
  -d '{"name": "string", "major": "string", "goal": "未填写"}'
```

逐段拆开：

| 部分 | 含义 |
|---|---|
| `curl` | 工具本身 |
| `-X 'POST'` | 用 POST 方法（X = method） |
| `'http://127.0.0.1:8001/profile'` | **目标地址**——回答"调谁"，必需 |
| `-H 'accept: */*'` | 请求头：我能接受任何返回格式 |
| `-H 'Content-Type: application/json'` | 请求头：我发给你的**是 JSON** |
| `-d '{...}'` | 请求体，要发送的数据 |
| 行尾的 `\` | "这行没完，下一行接着"（换行连写） |

### 8.1 一个请求由什么组成

**方法 + 地址 + 请求头 + 请求体**。这四样是所有 HTTP 请求的共同结构：

| 部分 | 回答的问题 |
|---|---|
| 方法（POST / GET） | **要干什么** |
| 地址（URL） | **对谁干** |
| 请求头（Headers） | **附带说明**（发的是 JSON、能接受什么格式、身份凭证…） |
| 请求体（Body） | **具体内容** |

### 8.2 动手试试

把上面那段**粘到 Git Bash 里运行**。

> ⚠️ 别用 PowerShell——PowerShell 里的 `curl` 是 `Invoke-WebRequest` 的别名，语法和参数都不一样，会报奇怪的错。

看它返回什么。结果和你刚才在 `/docs` 点 "Try it out" 是一样的——**只是换了个入口**。

### 8.3 为什么这件事重要

同一个接口，可以有**三个入口**调用它：

1. **浏览器** —— `/docs` 页面
2. **curl** —— 命令行
3. **前端代码** —— JavaScript 的 `fetch` / `axios`

> **你的前端以后就是这样调后端的**，只不过把 curl 换成 JavaScript。
> 所以你现在理解的这套结构，过几周做前端时可以直接复用。
