## 二、脚本和服务，是两种生物

先看清楚一个根本差别——对比一下 `db_demo.py` 和 `main.py`：

| | `db_demo.py`（脚本） | `main.py`（服务） |
|---|---|---|
| 跑几次 | **一次**，跑完就退出 | **一直活着**，被调用成千上万次 |
| 数据从哪来 | 写死在代码里 | 来自用户（`req`） |
| 生命周期 | 从头走到尾的一条直线 | 无数次"被唤醒 → 处理 → 等待" |
| 谁决定何时运行 | 你敲回车 | 浏览器 / 前端 / 别的程序 |

> **一句话：脚本是"一条直线走到底"，服务是"无数次被唤醒"。**

这个差别会**直接影响每一行代码怎么写**。下面三个问题，都是从这个差别里长出来的。

## 三、问题 1：连接什么时候建、什么时候关？

`db_demo.py` 里是这样：开头 `connect`，结尾 `close`。**因为脚本只跑一次。**

但接口会被调用一万次。于是有两种写法：

**方案 A：每次请求都新建连接，用完就关**

```python
def create_profile(req: ProfileRequest):
    conn = sqlite3.connect("student.db")   # 这次请求专用
    ...
    conn.close()
```

**方案 B：服务启动时建一个连接，全局共用**

```python
conn = sqlite3.connect("student.db")       # 模块顶层，永不关闭

def create_profile(req: ProfileRequest):
    cur = conn.cursor()
    ...
```

## 四、问题 2：接口怎么回答"没找到"？

你还要加一个接口：按 id 查学生，比如 `GET /profile/1`。

那么 `GET /profile/99999`（不存在的 id）该怎么回应？

| 做法 | 前端拿到的 |
|---|---|
| 返回 `null` | HTTP **200**，内容是 `null` |
| 返回 `{}` | HTTP **200**，内容是 `{}` |
| 报错 404 | HTTP **404**，内容是错误说明 |

第 3 课你已经见过 **422**（Pydantic 挡下脏数据时自动返回的）。这次轮到你自己决定返回什么状态码了。

**关键认知**：**HTTP 状态码是给"程序"看的，不只是给人看的。**
前端代码里通常是这样写的：

```javascript
if (response.status === 404) {
    // 显示"查无此人"
}
```

前端没法从 `null` 里判断"是没找到"还是"后端出 bug 了"。**状态码承载的是"语义"，不是"好看不好看"。**

**你的任务**：写出你打算怎么回应，以及为什么。

## 五、问题 3：`main.py` 该拆了吗？

现在 `main.py` 是 34 行。等你把数据库操作也塞进去，会变成什么？

**判断一个文件该不该拆，有个很好用的判据：按"变化的理由"拆。**

- 什么时候改**接口定义**（路径、参数、返回格式）？→ 前端联调、需求变了
- 什么时候改**数据库操作**（表结构、SQL）？→ 数据模型变了

**这两个"变化的理由"不一样，所以它们是两个模块。**

这也是你项目后面要长成的样子——你这个系统会有一堆东西：用户画像、题库、LLM 调用、推荐算法……**全塞 `main.py` 的话，它迟早会变成没人敢改的 2000 行巨兽。**

> **实习中你几乎一定会接手一个这样的文件**。所以现在就从一开始养成习惯。

## 六、样板代码：`backend/db.py`

新建 `backend/db.py`。这部分是**结构样板**，我直接给你（第 5 课的 SQL 是你自己写的，直接搬过来）：

```python
import sqlite3

DB_PATH = "student.db"


def get_conn():
    """打开一个新的数据库连接。"""
    return sqlite3.connect(DB_PATH)


def init_db():
    """建表（如果还不存在）。服务启动时调用一次。"""
    conn = get_conn()
    cur = conn.cursor()
    cur.execute("""
    create table if not exists students(
        id integer primary key autoincrement,
        name text not null,
        major text not null,
        age integer default 0
        )
    """)
    conn.commit()
    conn.close()
```

**注意这里把"连接"包成了函数 `get_conn()`。** 这是第 6 课的内容落地——你不再到处写 `sqlite3.connect(...)`，而是调用一个**你自己命名的动作**。

## 十、附录：写库 / 读库，代码里到底长什么样

### 10.0 先破词

「写库」「读库」是**行话**，不是新技术：

| 说法 | 就是执行这种 SQL | 特点 |
|---|---|---|
| **写库** | `insert` / `update` / `delete` | **会改变**数据 |
| **读库** | `select` | **只读**，不改变任何东西 |

**你在 `db_demo.py` 里两件事都做过了。** 所以这里没有新知识——只是把那段代码**搬个地方**。

### 10.1 唯一真正变的东西

```python
# db_demo.py：值是写死的
cur.execute("insert into students(name, major, age) values (?, ?, ?)",
            ("张三", "计算机", 20))

# 接口里：值来自用户发来的 req
cur.execute("insert into students(name, major, age, goal) values (?, ?, ?, ?)",
            (req.name, req.major, req.age, req.goal))
```

**结构一模一样，只有第二个参数换了来源。** 就这一点。

### 10.2 写库的骨架

在 `main.py` 顶部加 `import db`，然后：

```python
app = FastAPI()
db.init_db()          # 启动时建表 —— 注意，它会在每次启动都执行


@app.post("/profile")
def create_profile(req: ProfileRequest):
    conn = db.get_conn()          # sqlite3.Connection —— 连接对象
    cur = conn.cursor()           # sqlite3.Cursor     —— 游标对象

    cur.execute(
        "insert into students(name, major, age, goal) values (?, ?, ?, ?)",
        (req.name, req.major, req.age, req.goal),
    )                             # 返回值游标本身，你不用管它
    new_id = cur.lastrowid        # int —— 属性！没有括号
    conn.commit()                 # 确认落盘（第 5 课坑 1）
    conn.close()                  # 这次请求用完了，关掉

    return {"id": new_id}
```

**逐段看类型**（这是第 6 课的应用）：

| 代码 | 是什么 | 返回什么 |
|---|---|---|
| `db.get_conn()` | 函数 | `sqlite3.Connection` |
| `conn.cursor()` | 方法（有括号） | `sqlite3.Cursor` |
| `cur.execute(sql, params)` | 方法 | 游标自己（可以链式调用，不管） |
| `cur.lastrowid` | **属性**（无括号） | `int`，刚才插入那行的 id |
| `conn.commit()` | 方法 | `None` |

> `lastrowid` 是**属性**，就像第 6 课说的 `.xxx` 和 `.xxx()` 的区别。
> 写成 `cur.lastrowid()` 会报 `TypeError: 'int' object is not callable` —— "int 不能被调用"，一看就知道多写了括号。

### 10.3 读库的骨架

```python
@app.get("/profile/{student_id}")
def get_profile(student_id: int):          # 路径参数，第 3 课学过
    conn = db.get_conn()
    cur = conn.cursor()

    cur.execute(
        "select id, name, major, age, goal from students where id = ?",
        (student_id,),                     # ← 注意这个逗号
    )
    row = cur.fetchone()                   # tuple 或 None
    conn.close()

    if row is None:                        # 没查到
        raise HTTPException(status_code=404, detail="不存在该学生")

    return {
        "id": row[0],
        "name": row[1],
        "major": row[2],
        "age": row[3],
        "goal": row[4],
    }
```

需要 `from fastapi import HTTPException`。

**这里有两个新东西：**

**① `raise HTTPException(...)` —— 注意是 `raise`，不是 `return`**

它不是"返回一个错误"，而是**抛出异常**。FastAPI 接住它，自动转成对应状态码的 HTTP 响应，并**立刻结束这个函数**。

> 为什么用抛异常而不是 `return {"error": ...}`？
> 因为**函数里的任何一层**都能一抛就中断，不用一层层往上传错误码。
> 这是 Python（和大多数语言）处理错误的通用方式，以后你会天天见。

**② `fetchone()` 返回的是 tuple，不是 dict**

| 方法 | 返回类型 | 取不到时 |
|---|---|---|
| `fetchall()` | `list[tuple]` | `[]` |
| `fetchone()` | `tuple` | `None` |

所以 `row[0]` 是**第 1 列**。**按 select 里列的顺序取值**，改顺序必崩。

> ⚠️ **`(student_id,)` 那个逗号必须有。** 单元素元组要写逗号——`(student_id)` 只是"加了括号的整数"，`(student_id,)` 才是元组。`execute` 要的是元组，少了逗号会报 `parameters are of unsupported type`。这个坑几乎人人踩一次。

### 10.4 骨架里故意没给你的部分

1. **`db.init_db()` 放在模块顶层，意味着每次启动都会执行一次。** 你的 `init_db()` 现在扛得住吗？（第七节 7.3 说过的那件事）
2. **如果 `cur.execute` 抛异常了，`conn.close()` 会执行吗？** 想想这个问题，第 8 课会讲。
3. **如果 `select` 里的列顺序改了，`row[0]` 还对吗？** 这就是后面要学 ORM 的原因之一。

### 10.5 一个小习惯：`select` 别写 `select *`

写明列名。理由：`*` 依赖列的顺序，别人改表你就崩；而且表变大以后会把用不上的大字段也捞出来。
