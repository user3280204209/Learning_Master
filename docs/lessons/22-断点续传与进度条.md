> **日期**：2026-10-27
> **目标**：把「分片上传」升级成可暂停、可继续、有进度反馈的完整文件传输链路。
> **对应代码**：`backend/routers/upload.py`、`frontend/src/components/UploadLab.vue`、`backend/test_upload.py`
> **配套文档**：`docs/原理-上传下载断点续传.md`（流程/契约）、`docs/演示脚本-上传下载断点续传.md`（录屏）

---

## 一、先分清三个词

| 概念 | 含义 | 本项目落点 |
|---|---|---|
| 分片上传 | 把大文件切成 N 片，逐片上传 | `POST /api/upload/chunk` |
| 断点续传 | 暂停/失败后，只补没传完的部分 | `GET /api/upload/status/{file_id}` + 只传 `missing` |
| 进度条 | 用真实字节事件计算百分比 | 上传 `XHR.upload.onprogress`；下载 `ReadableStream` |

**断点续传不是「把整个文件重传一遍」。** 它的核心是：服务端能回答「我已经有哪些部分」，客户端只补缺失部分。

## 二、上传链路

### 1. 前端切片

```js
const start = index * chunkSize
const end = Math.min(file.size, start + chunkSize)
const blob = file.slice(start, end)   // 浏览器原生切片，不读整文件进内存
```

每片用 `FormData` 发送：

```js
form.append('file_id', fileId)
form.append('chunk_index', String(index))
form.append('file', blob, `chunk-${index}`)
```

`file_id` 是本次上传的唯一标识。项目用「文件名 + 大小 + lastModified」做指纹，把 `file_id` 存进 `localStorage`；刷新页面后重新选择同一个文件，仍能找回上次的分片目录。

### 2. 服务端落盘

```python
chunk_dir = UPLOAD_ROOT / safe_id
chunk_path = chunk_dir / str(chunk_index)
with chunk_path.open("wb") as f:
    f.write(await file.read())
```

目录结构：

```text
uploads/
└── 1f0c...-uuid/
    ├── 0
    ├── 1
    ├── 2
    └── ...
```

分片按序号命名，**天然支持乱序到达和重复上传**（同一序号覆盖即可）。

### 3. 查询断点

```python
@router.get("/status/{file_id}")
def upload_status(file_id: str, total_chunks: int = 0):
    uploaded = sorted(int(p.name) for p in chunk_dir.iterdir() if p.name.isdigit())
    missing = [i for i in range(total_chunks) if i not in set(uploaded)]
    return {"uploaded": uploaded, "missing": missing, ...}
```

前端「继续上传」时：

```js
const status = await api.uploadStatus(fileId, totalChunks)
// 已上传的标记为 done，只循环 missing
```

这就是断点续传的核心循环。

### 4. 合并

```python
for i in range(total_chunks):
    with (chunk_dir / str(i)).open("rb") as f:
        shutil.copyfileobj(f, out)
shutil.rmtree(chunk_dir)
```

注意：**必须按 0..N 顺序拼接**，不能依赖文件系统遍历顺序。合并成功后清理临时目录。

## 三、上传进度条

分片上传用 `XMLHttpRequest`，因为它有 `upload.onprogress`：

```js
xhr.upload.onprogress = (event) => {
  if (event.lengthComputable) onProgress(event.loaded)
}
```

整体进度不能只看当前片，要把已完成分片算进去：

```text
整体进度 = (已完成分片字节数 + 当前分片已上传字节数) / 文件总大小
```

前端实现：

```js
const uploadProgress = computed(() => {
  const loaded = completedBytes.value + currentLoaded.value
  return Math.round((loaded / file.value.size) * 100)
})
```

> `fetch` 默认没有上传进度事件，所以上传用 XHR；下载可以用 `fetch` 的流式响应。

## 四、下载断点续传

### 1. HTTP Range

暂停后继续，不要从 0 开始：

```http
GET /api/upload/download/demo-20mb.bin
Range: bytes=5177344-
```

服务端返回：

```http
HTTP/1.1 206 Partial Content
Content-Range: bytes 5177344-20971519/20971520
Content-Length: 15794176
Accept-Ranges: bytes
```

`206` 表示「只给你要的那一段」，不是完整文件。

### 2. 服务端实现

```python
match = re.fullmatch(r"bytes=(\d*)-(\d*)", range_header)
start = int(start_raw) if start_raw else 0
end = int(end_raw) if end_raw else total - 1
return StreamingResponse(
    iter_range(),
    status_code=206,
    headers={"Content-Range": f"bytes {start}-{end}/{total}", ...},
)
```

用 `StreamingResponse` 按 64KB 块读文件，避免把 20MB 一次读进内存。

### 3. 前端进度

```js
const reader = response.body.getReader()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  downloadChunks.value.push(value)
  downloadedBytes.value += value.length
}
```

总大小从 `Content-Range` 或 `Content-Length` 取：

```js
const match = contentRange.match(/\/(\d+)$/)
downloadTotal.value = Number(match[1])
```

### 4. 暂停/继续

```js
// 暂停
downloadController.value.abort()

// 继续
headers.Range = `bytes=${downloadedBytes.value}-`
```

`AbortController` 中断的是网络连接，**已经读到的字节还在内存里**；继续时从 `downloadedBytes` 开始请求。

> 本项目为了演示，把下载分片暂存在内存，页面刷新会丢。生产环境应使用 File System Access API 写入磁盘，或由服务端提供断点下载任务。

## 五、安全与边界

1. **路径穿越**：`file_id` / `filename` 都经过 `_safe_name`，只保留文件名，去掉 `../` 和路径分隔符。
2. **Range 解析**：只接受单段 `bytes=start-end`；非法 Range 返回 416。
3. **文件指纹**：仅用文件名不够，项目加了大小和修改时间；生产环境应加内容哈希。
4. **临时分片清理**：合并成功立即删除；长期未完成的分片需要定时任务清理。
5. **并发**：同一 `file_id` 同时上传同一序号可能互相覆盖；生产环境要加锁或使用唯一临时文件名 + 原子重命名。
6. **校验**：本项目用 `test_upload.py` 做 MD5 对比；生产环境应在合并后校验整体哈希。

## 六、实测记录

- 演示文件：20MB，1MB 一片，共 20 片。
- 上传到第 4 片时点击暂停：进度 20%，chunk 01–04 为绿色。
- 继续上传：服务端返回 `uploaded: [0,1,2,3]`，只补 05–20；最终合并成功。
- 下载到 25%（约 4.9MB）时暂停；继续时发送 `Range: bytes=5177344-`，服务端返回 206，最终 100%。
- 无页面 JS 错误；保存文件可用。

## 七、小文件批量上传

小文件不要一片一片传。项目提供 `POST /api/upload/batch`：

```text
5 个小文件
  → 全部 append 到同一个 FormData 的 files 字段
  → 一次 POST /api/upload/batch
  → 后端 upload_batch 循环落盘
  → 返回 count / total_size / files
```

前端 `UploadLab.vue::uploadBatch`：

```js
const form = new FormData()
batchFiles.forEach((item) => form.append('files', item.file, item.name))
xhr.open('POST', '/api/upload/batch')
xhr.upload.onprogress = ...   // 只有整体进度
```

后端 `upload.py::upload_batch`：

```python
for f in files:
    safe_filename = _safe_name(f.filename or "", "unnamed.bin")
    with (UPLOAD_ROOT / safe_filename).open("wb") as out:
        shutil.copyfileobj(f.file, out)
```

批量上传的适用边界：

| 适合 | 不适合 |
|---|---|
| 头像、图标、小文本、配置文件 | 大视频、大压缩包 |
| 数量多、单个小 | 需要单文件进度 / 断点续传 |
| 可以接受整批失败重来 | 单个失败不能影响其他文件 |

> 小文件的瓶颈是**文件数量和元数据操作**，不是带宽；一次请求带多个文件能减少 HTTP 往返。
> 但一个 XHR 只有整体进度，没有单文件进度；失败通常整批重来；超大文件仍应走分片上传。

实测：5 个约 180KB 的小文件，一次请求上传完成，服务端返回 `count=5`、总大小约 915KB，5 个下载链接都可用。
