而你的项目需求里写的是"**动态学生画像**、**随学随新**"——这意味着数据必须**记得住**。今天学数据库，就是为了解决这件事。

## 二、基本概念：表、行、列、主键

数据库用**表格**来组织数据，和 Excel 很像：

| id | name | major | age |
|---|---|---|---|
| 1 | 张三 | 计算机 | 20 |
| 2 | 李四 | 软件工程 | 21 |

术语对应：

| 术语 | 含义 | 上表里是什么 |
|---|---|---|
| **表（table）** | 一类东西的集合 | `students` 表 |
| **行（row）** | 一个个体 | 张三这一整行 |
| **列（column）** | 一个属性 | `name`、`major`、`age` |
| **主键（primary key）** | 每行的**唯一身份证** | `id` |

**主键为什么必要**：两个学生可能同名同专业，靠名字根本区分不开。主键保证**每一行都能被唯一地找到**。

> 💡 **和 Pydantic 的联系**：还记得上一课 `ProfileRequest` 里那些 `name: str` 吗？
> Pydantic 是**第一道防线**（挡住进来的脏数据），数据库约束是**最后一道防线**（挡住写进去的脏数据）。
> 一个系统里，数据要在多处被校验——这是常态，不是重复劳动。

## 三、为什么不用一个 txt 文件存

你可能会想：存数据嘛，写个 `students.txt` 不就行了？

| 问题 | txt 文件 | 数据库 |
|---|---|---|
| 两个人同时写 | 内容会互相覆盖 | 有锁机制，安全 |
| "找出所有年龄 > 20 的" | 得自己读全部、逐行解析 | 一句 SQL |
| 保证 age 是数字 | 靠自己检查 | 类型约束强制保证 |
| 数据量到 10 万行 | 慢得没法用 | 有索引，毫秒级 |

**一句话**：txt 是"能存"，数据库是"能**管**"。

## 四、为什么先学 SQL，再学 ORM

你以后一定会听到 **ORM**（比如 SQLAlchemy），它能让你**用 Python 对象操作数据库**，看起来很美好。

但**先别用**。原因：

> **ORM 只是一层翻译。** 它把你的 Python 代码翻成 SQL 发给数据库。
> 不懂 SQL 就用 ORM，一旦出错或性能出问题，**你根本不知道底下发生了什么**。

所以顺序是：**先手写 SQL 搞懂原理，再上 ORM 提升效率。** 这也是本课的设计。

## 五、SQLite 是什么

**SQLite** 是一个数据库，但它很特别：

- **一个文件就是一个完整的数据库**（不像 MySQL 要装服务、开端口）
- **Python 标准库自带**，`import sqlite3` 就能用，不用 `pip install`
- 全世界用得最多的数据库，你的手机里就有好几个

**为什么先用它**：零配置、零安装，适合起步。以后数据量大了想换 PostgreSQL，**只要改连接那段代码**，其余基本不动。

## 六、动手：让 Python 和数据库对话

在 `backend/` 下新建 `db_demo.py`（这是个学习用的临时脚本，不接 FastAPI）：

```python
import sqlite3

# 1. 连接数据库（文件不存在会自动创建）
conn = sqlite3.connect("students.db")
cur = conn.cursor()

# 2. 建表
cur.execute("""
    CREATE TABLE IF NOT EXISTS students (
        id      INTEGER PRIMARY KEY AUTOINCREMENT,
        name    TEXT NOT NULL,
        major   TEXT,
        age     INTEGER DEFAULT 0
    )
""")
conn.commit()

# 3. 插入一条数据
cur.execute(
    "INSERT INTO students (name, major, age) VALUES (?, ?, ?)",
    ("张三", "计算机", 20),
)
conn.commit()

# 4. 查询
cur.execute("SELECT * FROM students")
rows = cur.fetchall()
print(rows)

# 5. 关闭连接
conn.close()
```

跑它：

```bash
cd backend
source .venv/Scripts/activate
python db_demo.py
```

## 七、逐段讲解

### 7.1 连接与游标

```python
conn = sqlite3.connect("students.db")
cur = conn.cursor()
```

- `connect` 建立连接。**文件不存在会自动创建**——所以跑完你会看到一个 `students.db` 文件
- `cursor`（游标）是"执行 SQL 的那只手"。`conn` 管连接，`cur` 管执行

> 为什么要有游标？因为一个连接上可能同时有多个"操作序列"在进行，游标用来追踪"我执行到哪了"。

### 7.2 SQL 语句里的约束

```sql
CREATE TABLE IF NOT EXISTS students (
    id      INTEGER PRIMARY KEY AUTOINCREMENT,
    name    TEXT NOT NULL,
    major   TEXT,
    age     INTEGER DEFAULT 0
)
```

| 写法 | 含义 |
|---|---|
| `IF NOT EXISTS` | 表已存在就别报错（**很重要**，否则脚本跑第二次就崩） |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | 整数主键，自动递增（1, 2, 3…） |
| `TEXT NOT NULL` | 必须是文本，**且必须有值** |
| `INTEGER DEFAULT 0` | 整数，可以不填，默认 0 |

**注意 `name` 写了 `NOT NULL`，`major` 没写**——这决定了插入时哪个字段可以省略。和 Pydantic 里"有没有默认值"是同一个道理。

### 7.3 `?` 占位符（**这条最重要，别写错**）

```python
cur.execute(
    "INSERT INTO students (name, major, age) VALUES (?, ?, ?)",
    ("张三", "计算机", 20),
)
```

`?` 是占位符，真实的值作为**第二个参数**传进去。

> ⚠️ **绝对不要**用 f-string 把值拼进 SQL：
> ```python
> cur.execute(f"INSERT INTO students (name) VALUES ('{name}')")   # ❌ 危险！
> ```
> 为什么危险，看第八节。

## 八、两个必须避开的坑

### 坑 1：不 `commit` 等于白干

```python
cur.execute("INSERT INTO ...")
conn.commit()        # ← 少了这一行，数据不会真正写进去
```

**为什么要有 `commit`**：数据库为了效率，先把改动放在内存里，`commit` 才是"确认，落盘"。

> 💡 这跟 Git 的 `commit` **不是一回事**（那个是存档到历史），但精神相通：
> **都是"我确认这次改动生效"这个动作。** 名字撞车是巧合。

### 坑 2：SQL 注入

假设你图省事写成这样：

```python
cur.execute(f"SELECT * FROM students WHERE name = '{name}'")
```

正常情况没问题。但如果有人把 `name` 填成：

```
' OR '1'='1
```

拼出来的 SQL 就变成了：

```sql
SELECT * FROM students WHERE name = '' OR '1'='1'
```

**`'1'='1'` 永远成立 → 所有数据都被查出来了。**

更狠的输入还能直接删表。这就是 **SQL 注入**，是 Web 安全史上最经典的漏洞之一，**OWASP 排行榜上常年霸榜**。

更狠的输入是 `'; DROP TABLE students; --`，拼出来变成：

```sql
SELECT * FROM students WHERE name = ''; DROP TABLE students; --'
```

**整张表直接被删掉。**（末尾的 `--` 是 SQL 注释符，把剩下的引号注释掉，让语句合法。）

### 原理：为什么 `?` 就安全了

关键在于——**SQL 的"结构"和"数据"，是在两个不同阶段被处理的。**

**用 f-string 拼接时**：Python 先做字符串拼接，拼出一个**已经成型的完整 SQL 语句**，再送给数据库。数据库拿到它时**只能照着解析**——它分不清哪部分是"你写的代码"、哪部分是"用户输入的数据"。

> **问题的根源：用户输入被当成了"代码"。**

**用 `?` 占位符时**，顺序反过来了：

1. 数据库先拿到 **`SELECT * FROM students WHERE name = ?`** 这个**带洞的模板**，**先把它解析好**（此时它已经确定了这句话的结构）
2. **然后**才把 `name` 的值，作为**纯数据**填进那个洞里

**第 2 步填进去的东西，永远不会被当成 SQL 代码重新解析。** 哪怕你填的是 `' OR '1'='1`，数据库也只当它是"一个字符串值"，去找有没有人叫这个名字——当然找不到。

> **一句话**：`?` 让数据库**先定好语句结构，再填数据**。用户输入永远待在"数据"的位置，爬不到"代码"的位置。

### 一个类比

| 写法 | 类比 |
|---|---|
| **f-string 拼接** | 把用户说的话**直接抄进合同正文**。他说"本合同作废"，合同里就真有这句话了 |
| **`?` 占位符** | 合同是**预先印好的模板**，用户只能填进**"姓名：____"**那个空格里。他写得再离谱，也只是"姓名"栏里的内容 |

### 补充两点

- 这是**数据库引擎层面的机制**（叫 prepared statement / 参数化查询），不是 Python 的小技巧。**任何语言、任何数据库都一样。**
- 附带好处：同一个模板重复执行时，第 1 步的解析可以**复用**，所以也更快。

> **实习面试常考这个。** 现在你能讲清"为什么要用占位符"，而不只是"老师说不能拼字符串"——**这是两个档次。**

## 附录：f-string 是什么（`f` 和 `{}` 的用法）

### 一句话

> **`f` 是"模板开关"，`{}` 是"要填的空"。**

### 三个例子对比

```python
name = "张三"

print("你好，{name}")                  # 你好，{name}      ← 没 f，花括号是普通字符
print(f"你好，{name}")                 # 你好，张三         ← 有 f，{} 里被替换
print(f"我叫{name}，今年{20}岁")        # 我叫张三，今年20岁  ← {} 里可以放任何东西
```

### 拆开看

| 部分 | 作用 |
|---|---|
| `f` | **前缀**，告诉 Python"这个字符串里有要替换的地方" |
| `"..."` | 普通字符串 |
| `{ }` | **占位符**——运行时把里面的东西算出来，替换成结果 |

**关键**：`{}` 里**不只能是变量名**，可以是任何**表达式**：

```python
a, b = 3, 5
print(f"{a} + {b} = {a + b}")       # 3 + 5 = 8      ← 能算数
print(f"数据共 {len(rows)} 条")      # len() 也行
print(f"{name.upper()}")             # 方法调用也行
```

### 什么时候用，什么时候不能用

**f-string 本身是好东西**——日常写日志、拼消息非常方便：

```python
print(f"用户 {name} 登录失败，IP: {ip}")     # ✅ 好用法
```

**唯一不能用的地方：拼 SQL。**

因为 SQL 是**代码**，不是普通文本。把用户输入拼进去，等于让用户**改写你的程序**。这就是上一节的 SQL 注入。

> **记住这条分界线**：
> - 拼**给人看的文本** → 用 f-string，方便
> - 拼**给机器执行的代码**（SQL、shell 命令、表达式） → **必须用参数化 / 占位符**

### 回过头看第 3 课那个"多余的 f"

```python
f"这是我第一个 FastAPI 应用程序！"    # ❌ 没有 {}，f 是多余的
```

**开了模板开关，却没开洞。** 功能上没错，属于冗余写法，所以 Ruff 会提示。
